Đóng góp 1: Chế độ chấm điểm linh hoạt (Scoring Mode)

Mở rộng từ boolean partial sang 3 chế độ chấm, giữ tương thích ngược với judge gốc

Short Circuit

All-or-nothing

  • Dừng ngay khi gặp test sai
  • "Được tất cả hoặc không gì"
  • Phù hợp bài ACM/ICPC

Partial by Subtask

Kiểu IOI (mặc định)

  • Chấm theo subtask/batch
  • 1 test sai → subtask đó 0 điểm
  • Các subtask khác vẫn tính

Partial by Testcase

Cộng dồn từng test

  • Mỗi test đúng đều cộng điểm
  • Linh hoạt cho bài luyện tập
  • Khuyến khích giải từng phần

Thiết kế kỹ thuật

  • ▸ Thêm trường scoring_mode trên model Problem (migration 0222)
  • ▸ Trường boolean short_circuit cũ được tự động tính từ scoring_mode trong Problem.save() → tương thích ngược với judge gốc
  • ▸ Logic gom test theo batch/subtask tại judge/views/submission.py (group_test_cases, make_batch)

Đóng góp 3: AI Code Review

Phân tích mã nguồn tự động bằng AI, hỗ trợ 4 nhà cung cấp

AI phân tích 5 khía cạnh

  • 1 Thuật toán & CTDL — nhận diện thuật toán chính
  • 2 Luồng thực thi — giải thích từng bước code hoạt động
  • 3 Độ phức tạp thời gian — O(n), O(n log n), ...
  • 4 Độ phức tạp bộ nhớ — phân tích space complexity
  • 5 Chất lượng code — gợi ý cải thiện, edge cases

Đánh giá năng lực người dùng

  • AI trả thêm dòng TAGS: → gắn nhãn chủ đề cho bài nộp
  • Lưu vào UserProblemTag → dựng hồ sơ năng lực
  • Trang UserProgressPage tổng hợp điểm mạnh/yếu theo dạng bài

Luồng xử lý

User xem source code (/src/<id>/)
    │
    ▼ Click "Review with AI"
    │
Modal: Chọn Provider, Model, Ngôn ngữ
    │
    ▼ POST /src/<id>/ai-review/
    │
Server:
  ├─ Kiểm tra quyền sở hữu
  ├─ Lấy API key (giải mã Fernet)
  ├─ Tạo prompt từ template
  ├─ Gọi API provider (timeout 120s)
  ├─ Parse response
  ├─ Trích xuất TAGS (nếu AC)
  ├─ Lưu AICodeReview + UserProblemTag
  └─ Trả JSON response
    │
    ▼
Frontend hiển thị kết quả
(Lần sau: trả từ cache)

Đóng góp 4: AI Problem Creator & Generate Testcase

AI Problem Creator

Tạo đề bài tự động từ ảnh/PDF bằng AI Vision

  • Upload ảnh (PNG, JPG, WebP) hoặc PDF
  • AI trích xuất nội dung: tên bài, mô tả, ràng buộc, ví dụ I/O
  • Xuất ra Markdown chuẩn OJ
  • Hỗ trợ: OpenAI, Gemini, Claude (có Vision)
  • Admin review và chỉnh sửa trước khi lưu
Luồng: Upload file → Encode base64 → Gọi Vision API → Parse response → Điền vào form problem

AI Generate Testcase (GenSol)

Sinh test case tự động qua pipeline Bridge/Judge

  • Nhập generator (sinh input) + solution (sinh output)
  • Chọn ngôn ngữ và số lượng test (1-50)
  • Judge biên dịch & chạy generator → input
  • Judge biên dịch & chạy solution → output
  • Auto upload vào ProblemData
Trạng thái: PENDING → GENERATING_INPUT → GENERATING_OUTPUT → UPLOADING → DONE

AI Suggest Tags — Gợi ý dạng đề tự động

  • Lấy 3 bài AC nhanh nhất + mô tả đề → gửi cho AI
  • AI trả về mảng tag ID → kiểm định với ProblemType trong CSDL
  • Gợi ý gắn nhãn nhất quán cho kho đề (trang admin)

Đóng góp 5: Quản lý API Key & Bảo mật

🔐 Mã hóa API Key (Fernet)

  • ▸ API key được mã hóa bằng Fernet (AES-128-CBC)
  • ▸ Key derivation: SHA-256 từ Django SECRET_KEY
  • ▸ Chỉ lưu ciphertext + 4 ký tự cuối (last4)
  • ▸ Giải mã chỉ khi gọi API thực sự
  • ▸ Plaintext bị xóa khỏi memory ngay sau khi dùng

Quy trình sử dụng

  • Thêm key → Trạng thái Pending
  • Test connection → Verified / Failed
  • Log đầy đủ: thời gian, model, kết quả, response time (ms)
  • Mỗi user 1 key/provider, hỗ trợ 4 providers

🛡️ Bảo mật nhiều lớp (Defense-in-depth)

LớpBiện pháp
Xác thựcLogin, OAuth2, 2FA (TOTP + WebAuthn)
Ứng dụngChống XSS, CSRF, rate-limit nộp bài
Dữ liệuFernet encryption, Django ORM (SQL injection)
Thực thiSandbox cptbox, giới hạn tài nguyên
Hạ tầngDocker network isolation, DB không expose

Đóng góp 6: Contest Focus Lock & Chống gian lận

Cơ chế hoạt động

  • 1 Admin bật enable_focus_lock cho contest
  • 2 Thí sinh tham gia → giao diện yêu cầu fullscreen, ẩn thanh điều hướng
  • 3 Phát hiện mất focus / đổi tab / thoát fullscreen → ghi nhận vi phạm
  • 4 Server cập nhật nguyên tử (F() expression) số lần vi phạm
  • 5 Vượt ngưỡng → auto-ban tự động

Chặn phím tắt khi thi

  • Chặn Ctrl+R, F5 (reload)
  • Chặn F11 (thoát fullscreen)
  • Chặn Escape (Chrome Keyboard Lock)
  • Ghi nhận Alt+Tab, click ngoài cửa sổ

Auto-ban workflow

Thí sinh thoát tab / mất focus
        │
        ▼
POST /contest/report_focus_violation
        │
        ▼
focus_violations += 1 (F() atomic)
        │
        ▼
violations > MAX_DISQUALIFICATIONS?
  ├─ YES → check_ban() → ban_user()
  │        → disqualify khỏi contest
  └─ NO  → tiếp tục thi
        │
  (Khi giảm dưới ngưỡng → unban_user())
⚠ Giới hạn: Cơ chế web không thể thay thế proctoring chuyên dụng, nhưng tạo rào cản đáng kể cho gian lận thông thường.

Cấu hình

BKDNOJ_SHOULD_BAN_FOR_CHEATING = False BKDNOJ_MAX_DISQUALIFICATIONS_BEFORE_BANNING = 3

Hệ thống Rating Elo-MMR & Bảng xếp hạng

Rating Elo-MMR

  • ▸ Thuật toán dựa trên bài báo "An Elo-like System for Massive Multiplayer Competitions" (Ebtekar & Liu)
  • ▸ Cập nhật sau mỗi contest có is_rated = True
  • ▸ Lưu mean/variance/performance cho mỗi người dùng
  • ▸ Rating tiers: phân hạng theo mốc (màu/nhãn) trên hồ sơ
